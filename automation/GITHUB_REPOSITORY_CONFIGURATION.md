# GitHub Repository Configuration Guide

This guide explains the required GitHub repository configuration for the CI/CD pipeline.

## Required Settings

### 1. GitHub Pages

**Location:** Repository Settings → Pages

**Configuration:**
- **Source:** Deploy from a branch
- **Branch:** `gh-pages` (or `main` if using root)
- **Folder:** `/ (root)` or `/docs`

**Steps:**
1. Go to repository Settings
2. Click on "Pages" in left sidebar
3. Under "Build and deployment", select "Source" as "Deploy from a branch"
4. Select branch: `gh-pages` (recommended) or `main`
5. Select folder: `/ (root)`
6. Click Save

**Note:** The workflow automatically creates the `gh-pages` branch on first deployment.

### 2. Actions Permissions

**Location:** Repository Settings → Actions → General

**Workflow Permissions:**
- Select "Read and write permissions"
- Enable "Allow GitHub Actions to create and approve pull requests"

**Steps:**
1. Go to repository Settings
2. Click on "Actions" in left sidebar
3. Click on "General"
4. Under "Workflow permissions", select "Read and write permissions"
5. Click Save

### 3. Branch Protection

**Location:** Repository Settings → Branches

**Recommended Rules for `main` branch:**
- Require a pull request before merging
- Require status checks to pass before merging
- Require branches to be up to date before merging
- Enable "Require conversation resolution before merging"

**Steps:**
1. Go to repository Settings
2. Click on "Branches" in left sidebar
3. Click "Add rule" for `main` branch
4. Configure required checks
5. Click Save

### 4. Secrets (Optional)

**Location:** Repository Settings → Secrets and variables → Actions

**Required Secrets:**
- None required (workflow uses GITHUB_TOKEN automatically)

**Optional Secrets:**
- `CUSTOM_BASE_URL` - Override default BASE_URL
- `SLACK_WEBHOOK_URL` - Send notifications to Slack
- `EMAIL_NOTIFICATION` - Send email notifications

**Steps:**
1. Go to repository Settings
2. Click on "Secrets and variables" → "Actions"
3. Click "New repository secret"
4. Add secret name and value
5. Click Add secret

### 5. Environment (Optional)

**Location:** Repository Settings → Environments

**Create Environment:**
- Name: `production`
- Add protection rules as needed
- Add secrets specific to environment

**Steps:**
1. Go to repository Settings
2. Click on "Environments" in left sidebar
3. Click "New environment"
4. Enter name: `production`
5. Add protection rules
6. Click Save

## Workflow Configuration

### Workflow File

**Location:** `.github/workflows/deploy-and-test.yml`

**Key Configuration:**

```yaml
env:
  BASE_URL: https://${{ github.repository_owner }}.github.io/${{ github.event.repository.name }}/
  PYTHON_VERSION: '3.11'
  NODE_VERSION: '20'
```

**Customization:**
- Modify `PYTHON_VERSION` if using different Python version
- Modify `NODE_VERSION` if using different Node.js version
- Override `BASE_URL` using secret if needed

## Repository Visibility

### Public Repository

- GitHub Pages is automatically enabled
- No additional configuration needed
- Workflow runs without restrictions

### Private Repository

- GitHub Pages may have restrictions
- Ensure Actions permissions are set correctly
- Verify GITHUB_TOKEN has required permissions

## Branch Strategy

### Recommended Branch Structure

```
main (production)
  └── gh-pages (auto-generated by workflow)

develop (staging)
  └── gh-pages (auto-generated by workflow)

feature/* (feature branches)
  └── No deployment
```

### Branch Protection Rules

**Main Branch:**
- Require pull request
- Require status checks
- Require up to date
- Conversation resolution

**Develop Branch:**
- Require pull request (optional)
- Require status checks (optional)

**Feature Branches:**
- No protection required

## Permissions

### Required Permissions

The workflow requires the following permissions:

```yaml
permissions:
  contents: write
  pages: write
  id-token: write
```

These are automatically granted via `GITHUB_TOKEN`.

### Third-Party Integrations

If using third-party integrations (Slack, email, etc.):

1. Add required secrets
2. Configure integration in workflow
3. Test integration manually

## Webhooks

### Required Webhooks

None required - workflow triggers on push/PR.

### Optional Webhooks

For external notifications:
1. Go to repository Settings
2. Click on "Webhooks"
3. Add webhook URL
4. Configure events (push, pull_request)

## Custom Domain (Optional)

### Configure Custom Domain

1. Go to repository Settings → Pages
2. Under "Custom domain", enter your domain
3. Configure DNS records:
   - CNAME: `your-domain.com` → `username.github.io`
   - A: `your-domain.com` → GitHub Pages IP
4. Enable "Enforce HTTPS"

### Update Workflow

If using custom domain, update BASE_URL:

```yaml
env:
  BASE_URL: https://your-custom-domain.com/
```

## Monitoring

### Enable Notifications

1. Go to repository Settings
2. Click on "Notifications"
3. Configure email notifications
4. Configure webhook notifications (optional)

### Monitor Workflow Runs

1. Go to repository → Actions
2. View workflow runs
3. Check for failures
4. Download artifacts for detailed analysis

## Security Best Practices

1. **Never hardcode secrets** - Use GitHub Secrets
2. **Limit permissions** - Grant only required permissions
3. **Enable branch protection** - Protect main branch
4. **Require reviews** - Require PR reviews for main
5. **Monitor access** - Regularly review repository access
6. **Update dependencies** - Keep dependencies updated
7. **Audit logs** - Regularly review audit logs

## Verification Checklist

Before running the pipeline for the first time:

- [ ] GitHub Pages is enabled
- [ ] Actions permissions are set to "Read and write"
- [ ] Branch protection rules are configured
- [ ] Workflow file is present in `.github/workflows/`
- [ ] Required secrets are added (if any)
- [ ] Custom domain is configured (if needed)
- [ ] Notifications are configured (optional)
- [ ] Repository visibility is set correctly

## Troubleshooting Configuration Issues

### GitHub Pages Not Enabled

**Error:** "GitHub Pages is not enabled for this repository"

**Solution:**
1. Go to Settings → Pages
2. Enable GitHub Pages
3. Select source branch
4. Save settings

### Workflow Permission Denied

**Error:** "Resource not accessible by integration"

**Solution:**
1. Go to Settings → Actions → General
2. Set workflow permissions to "Read and write"
3. Save settings

### Branch Protection Blocking

**Error:** "Branch protection rules prevent this action"

**Solution:**
1. Create pull request instead of direct push
2. Configure required status checks
3. Ensure branch is up to date

### Deployment Fails

**Error:** "Deployment failed"

**Solution:**
1. Check GitHub Pages settings
2. Verify source branch
3. Check build logs
4. Verify workflow permissions
